# Этап 5: перекрывающиеся OCR-блоки

Этап 5 не запускает OCR. Он получает выровненную PNG-страницу, точные
сегменты этапа 1 и partition объектов этапа 6, затем строит ограниченный набор
крупных контекстных блоков. Production-профиль `sparse_v20_standard`
использует `spatial_2d`; прежний `full_width` сохранён как совместимый режим
для повторения старых прогонов.

## Инварианты

- `core_segment_ids` всех блоков образуют точное упорядоченное разбиение
  исходных сегментов: без потерь, дубликатов и перестановок.
- `spatial_2d` группирует две соседние физические строки и до пяти соседних
  сегментов по горизонтали. Шаг равен одной строке и четырём сегментам, поэтому
  соседние окна пересекаются хотя бы по одному целому сегменту.
- Membership замыкается до fixed point по непадденному прямоугольнику: если
  bbox блока показывает хотя бы часть сегмента, этот сегмент обязан стать
  member. Поэтому PNG никогда не содержит OCR-текст, которому некуда
  маршрутизироваться.
- Crop является bounded union реальных bbox его member-сегментов. Padding
  применяется после closure и обрезается перед ближайшими excluded-сегментами,
  поэтому сам padding не запускает каскадное расширение блока.
- Обычные окна остаются локальными и не превращают одну ячейку в отдельный
  дорогой OCR-вызов. Реальный merged-сегмент шириной со строку может честно
  вынудить full-width union; в таком случае membership включает все видимые
  ячейки, а не скрывает их от этапа 2.
- Overlap — связный граф, а не предположение о соседстве номеров блоков.
  Для каждого ребра сохраняются `OR`/union, `XOR`, intersection, first-only и
  second-only в каноническом порядке исходных сегментов.
- Физические строки строятся транзитивным объединением сегментов с
  положительным пересечением half-open диапазонов по Y; простое касание границ
  не считается пересечением. Объединённая строка таблицы остаётся одним
  контекстным сегментом и соединяет окна соседних строк; rectangular closure
  не допускает видимых non-member ячеек вокруг неё.
- Для каждого блока сохраняются raw RGB и отдельный gamma-dark кандидат.
  Выбор между ними отложен до этапа 2; raw не заменяется фильтром заранее.
- `ObjectKind` не меняет геометрию блоков. Ownership этапа 6 используется
  только для точной привязки core-сегментов к объектам.
- План ограничен отдельными лимитами на блоки, пиксели, число member-сегментов,
  число появлений одного сегмента и число overlap-пар. Превышение даёт
  типизированную ошибку до частичной публикации.

## Совместимый full-width режим

`BlockPlanningMode.FULL_WIDTH` повторяет прежний алгоритм: физическая строка
атомарна, блок сохраняет полную ширину страницы, а следующий блок получает
левый контекст из предыдущей строки. Этот режим нужен для сопоставления с
v1–v19 и документов, где полный строковый контекст доказанно полезнее. Он не
является default нового production-профиля.

## Ограничения памяти

До декодирования страницы проверяются количество блоков, площадь каждого crop
и суммарная площадь всех crops. Raw и gamma создаются bounded batches, а
фактический суммарный размер результатов также ограничен. Tutorial renderer
пишет algebra/manifest для всех overlap-пар, но растровые OR/XOR-маски рисует
только для первых восьми: полный граф остаётся проверяемым без многогигабайтной
визуальной копии.

## Debug

Полный обучающий прогон SAMPLE с `spatial_2d`:

```bash
PYTHONPATH=ocr python3 \
  scripts/debug/debug_sparse_tutorial.py \
  --run-id sample-spatial-v20 \
  --block-mode spatial_2d \
  --report debag-report.md
```

Каждая страница сохраняет `05-blocks/manifest.json`, `blocks.jsonl`,
`algebra.jsonl`, исходную aligned PNG и пары `raw/` + `gamma/`. Публикация
резервирует run-каталог через atomic no-replace `mkdir` и удаляет partial при
ошибке.
